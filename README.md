# FlappyBird для Android

Учебная мобильная игра на **C# / .NET MAUI**, с **MVVM**, **SQLite** и **Entity Framework Core**. Работает без сервера и интернета.

## Что реализовано

- Классический полёт: касание при нажатии, гравитация, трубы, столкновения, счёт и повторная попытка.
- Меню, пауза с обратным отсчётом, экран результата, десять лучших попыток и настройки.
- Локальный профиль: имя, звуки, вибрация. Данные сохраняются через EF Core в SQLite.
- Автоматическая начальная миграция; повторное сохранение с тем же GUID не дублирует попытку.
- Рисованная графика на GraphicsView, анимация крыла и наклона, движущийся фон, три собственных звуковых эффекта.
- Медаль за результат: 10 / 25 / 50 / 100 очков. Без дополнительных режимов, магазина и сетевых функций.
- Портретная ориентация; при сворачивании игра ставится на паузу.

## Открытие в Visual Studio

1. Установите **Visual Studio 2022 17.14** с рабочей нагрузкой **«Разработка с помощью .NET Multi-platform App UI»**. В Visual Studio Installer проверьте наличие .NET 9 SDK, Android SDK Platform 35, Android Build Tools и Microsoft OpenJDK 17. Android-эмулятор необязателен при наличии телефона.
2. Клонируйте `https://github.com/Dertseg/FlappyBird.git` через меню **Git → Клонировать репозиторий** в папку с латинским путём, например **C:\Projects\FlappyBird**. Переключитесь на ветку **feature/android-mvvm-sqlite**. В установленном Android-инструментарии обнаружена ошибка AAPT2000 при упаковке в папке с кириллицей; латинский путь позволяет её избежать.
3. Откройте **FlappyBird.sln**. Дождитесь восстановления NuGet-пакетов.
4. В обозревателе решений нажмите правой кнопкой на **FlappyBird** → **Назначить запускаемым проектом**. Не выбирайте Core, Data или Checks.
5. На Android-телефоне включите режим разработчика и **отладку по USB**, подключите кабель с передачей данных и подтвердите доверие этому компьютеру.
6. Выберите телефон в списке устройств на панели Visual Studio. Выберите **Debug**, нажмите **F5**.
7. Для проверки сборки выпуска переключитесь на **Release**, соберите решение и запустите на том же телефоне.

Поддерживаются Android 6.0 / API 23 и новее. Для первого развёртывания требуются установленные Android SDK и принятые лицензии. Если телефон не виден, проверьте кабель, USB-драйвер и подтверждение отладки.

**Версии:** проект ориентирован на установленную среду .NET 9 / MAUI 9 и Visual Studio 2022. Поддержка MAUI 9 закончилась 12 мая 2026 года. Для долгосрочного развития следует обновить Visual Studio и MAUI до поддерживаемой версии, сменить целевые платформы в проектах и повторно проверить Release на телефоне. Источник: [политика поддержки MAUI](https://dotnet.microsoft.com/en-us/platform/support/policy/maui).

## Команды из терминала в корне решения

```powershell
dotnet restore FlappyBird.sln
dotnet run --project tests/FlappyBird.Checks -c Release
dotnet build src/FlappyBird/FlappyBird.csproj -c Debug
dotnet publish src/FlappyBird/FlappyBird.csproj -c Release -p:AndroidPackageFormats=apk
```

APK создаётся внутри `src/FlappyBird/bin/Release/net9.0-android/`. Для собственного распространения подпишите выпуск своим ключом в процессе публикации Visual Studio. Пароли и ключи не храните в Git. Отладочная подпись подходит для проверки на собственном телефоне, но не заменяет ключ публикации.

## Где SQLite и MVVM

| Проект | Ответственность |
|---|---|
| FlappyBird.Core | GameEngine, модели, интерфейсы хранилища/эффектов и MainViewModel с командами CommunityToolkit.Mvvm |
| FlappyBird.Data | GameDbContext, SqliteGameStore, миграции EF Core и фабрика для средств разработки |
| FlappyBird | XAML-интерфейс, отрисовка, ввод, Android-звуки и жизненный цикл |
| FlappyBird.Checks | Автоматические проверки физики, ViewModel и настоящей SQLite |

Code-behind передаёт касания, время кадра и события жизненного цикла; физики и SQL в нём нет. ViewModel управляет состоянием экранов и сохранением через интерфейс. Физика не зависит от MAUI. SQLite-операции выполняются последовательно вне UI-потока, с отдельным DbContext для каждой операции.

База `flappybird.db` находится в `FileSystem.AppDataDirectory` приложения, а не рядом с исходниками. Таблицы: `GameResults`, `PlayerSettings`, служебные таблицы EF. Сохраняются все завершённые попытки, интерфейс показывает топ-10. Переустановка с удалением приложения удаляет локальные данные; обычный перезапуск и обновление совместимой подписанной сборкой сохраняют их.

Миграции применяются при первом открытии базы через `Database.Migrate()`. `EnsureCreated()` не используется. Для дальнейшего изменения схемы:

```powershell
dotnet tool restore
dotnet ef migrations add NameOfChange --project src/FlappyBird.Data --output-dir Migrations
dotnet run --project tests/FlappyBird.Checks -c Release
```

DesignTimeFactory создаёт только проектную базу для инструментов; база телефона создаётся приложением. Не удаляйте старые миграции после распространения версии с пользовательскими данными.
