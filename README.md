# FlappyBird · FLAPPY / CLUB

Android-игра на **C# / .NET MAUI**, организованная по **MVVM**. Результаты, настройки и достижения сохраняются в локальной **SQLite** через **Entity Framework Core**. Сервер и подключение к интернету не требуются.

## Версия 2.0

- Пять отдельных страниц и пять ViewModel: главная, игра/результат, рекорды, достижения, настройки.
- Три сложности: лёгкий, обычный и сложный; отдельная таблица топ‑10 для каждой.
- Экран результата: длительность активного полёта, рекорд до попытки, лучший счёт уровня, медаль и оставшиеся до следующей медали очки.
- Первые три места отмечены медалями. Последняя сохранённая попытка выделяется рамкой и подписью. Если она не вошла в топ‑10, показывается сообщение о её счёте.
- Четыре постоянных достижения с прогрессом и датой получения. Новые достижения показываются после сохранения полёта.
- Светлый интерфейс, тёмные акцентные карточки, SVG-иллюстрации и нижняя навигация.
- Пауза при сворачивании, продолжение после отсчёта 3–2–1, повтор записи при ошибке сохранения.
- Начисление очков и физика работают независимо от XAML и частоты отрисовки.

## Открытие в Visual Studio

1. Используйте Visual Studio 2022 17.14 с рабочей нагрузкой **«Разработка с помощью .NET Multi-platform App UI»**, .NET 9 SDK, Android SDK Platform 35 и OpenJDK 17. Проект оставлен совместимым с установленной средой.
2. Клонируйте `https://github.com/Dertseg/FlappyBird.git` в папку **с латинским путём**, например `D:\FlappyBird-v2`. В существующей копии сначала сохраните или зафиксируйте свои изменения.
3. В **Git → Управление ветвями** переключитесь на **feature/game-experience-mvvm**. При необходимости выполните получение удалённых ветвей (Fetch).
4. Откройте **FlappyBird.sln**, дождитесь восстановления NuGet. В основном решении один проект — **FlappyBird**.
5. Подключите Android-телефон с включённой отладкой по USB, подтвердите доверие компьютеру, выберите устройство на панели Visual Studio.
6. Выберите **Debug / Any CPU** и нажмите **F5**. Для телефона поддерживается Android 6 / API 23 и новее; приложение не предназначено для запуска как Windows-программа.

**База создаётся и обновляется автоматически.** Устанавливать SQL Server и выполнять Update-Database для телефона не нужно. При обновлении старого приложения сохраняйте тот же ApplicationId и ключ подписи, не удаляйте приложение: удаление обычно стирает локальные данные. Если подписи различаются, перенос данных потребует отдельного решения; не удаляйте старую установку ради обхода ошибки подписи.

## Как проверить игру

1. В настройках задайте имя, звук и вибрацию, нажмите «Сохранить настройки».
2. На главной выберите сложность и начните полёт. Каждая пройденная пара труб даёт одно очко.
3. После столкновения проверьте длительность, прежний рекорд и прогресс медали. Дождитесь сообщения о сохранении.
4. Откройте рекорды: последняя попытка подсвечена, если входит в топ‑10. Переключите сложность — данные не должны смешиваться.
5. Откройте достижения кнопкой на главной или вкладкой «Награды». Наберите первое очко — откроется соответствующее достижение.
6. Полностью закройте и повторно запустите приложение: результаты, выбранный уровень, настройки и награды должны сохраниться.
7. Сверните игру во время полёта и во время отсчёта продолжения: после возврата должна сохраняться пауза.

## Структура MVVM

| Папка | Содержимое и ответственность |
|---|---|
| Models | GameEngine, DifficultyCatalog, GameResult, PlayerSettings, достижения и строки рекордов |
| ViewModels | HomeViewModel, GameViewModel, LeaderboardViewModel, AchievementsViewModel, SettingsViewModel; общая обработка загрузки и ошибок в BaseViewModel |
| Views | Пять XAML-страниц, общий StatusBanner, Drawing/GameRenderer |
| Data | IGameStore, SqliteGameStore, GameDbContext, миграции EF Core |
| Services | Навигация Shell, звук и вибрация |
| Resources | Иллюстрации, иконки, звуки и ресурсы запуска |
| Platforms | Android-точки входа и манифест |

В корне проекта: App.xaml, AppShell.xaml, GlobalXmlns.cs и MauiProgram.cs. Папки Behaviors, Converters и Messages оставлены для будущего расширения; пустые папки не содержат искусственной логики.

Code-behind отвечает только за события страницы, касания и таймер кадров. Запросов SQLite, начисления очков и бизнес-правил в нём нет. ViewModel взаимодействуют с IGameStore и INavigationService, а EF Core скрыт в Data. Для каждой операции создаётся отдельный DbContext, SQLite-операции выполняются последовательно вне UI-потока.

## Сложности и честное сравнение

| Уровень | Скорость труб | Ширина прохода |
|---|---:|---:|
| Лёгкий | 110 | 200 |
| Обычный | 130 | 166 |
| Сложный | 155 | 144 |

Числа заданы в единицах игрового мира 360 × 640. Гравитация и импульс птицы одинаковы. Сложность фиксируется при старте попытки. Рекорды выбираются по сложности; при равенстве очков выше более ранняя попытка. Один игрок может занимать несколько мест: это таблица лучших попыток.

## Достижения и медали

- **Первое очко** — 1 очко за попытку.
- **10 труб** — 10 очков за попытку.
- **25 труб** — 25 очков за попытку.
- **100 попыток** — 100 завершённых и сохранённых полётов.

Учитываются все сложности. Достижения сохраняются однократно в таблице Achievements и не теряются после перезапуска. Обычные медали результата: бронза — 10, серебро — 25, золото — 50, платина — 100 очков. Это отдельная система от медалей за первые три места таблицы.

Время результата — время симуляции активного полёта, без пауз и отсчёта. Завершение через кнопку на паузе фиксирует текущий счёт. Выход до первого взмаха не считается попыткой. Последняя строка подсвечивается в текущем сеансе приложения; сами результаты всегда сохраняются в SQLite.

## SQLite и обновление с версии 1

Файл `flappybird.db` расположен в `FileSystem.AppDataDirectory` приложения. Таблицы: GameResults, PlayerSettings, Achievements и история миграций EF Core.

Начальная миграция сохранена. Вторая миграция добавляет Difficulty, DefaultDifficulty и Achievements. **Все старые результаты относятся к обычному уровню**, их счёт, имя, дата и длительность остаются прежними. Существующие настройки сохраняются. Достижения за прошлые полёты выдаются при первом запуске обновления, с датой обнаружения достижения.

Результат и новые награды записываются в одной транзакции. GUID попытки предотвращает дубли при повторе сохранения. При ошибке доступны повтор и явный отказ; начало нового полёта и выход со страницы не удаляют несохранённый результат молча.

## Сборка и проверки

```powershell
dotnet restore FlappyBird.sln
dotnet run --project tests/FlappyBird.Checks -c Release
dotnet build src/FlappyBird/FlappyBird.csproj -c Debug
dotnet publish src/FlappyBird/FlappyBird.csproj -c Release -p:AndroidPackageFormats=apk
```

Проверки находятся вне основного решения и компилируют те же исходные файлы через ссылки, без копии бизнес-логики и без зависимости от Android. Они проверяют три сложности, физику, отдельные ViewModel, разделение рекордов, достижения, повтор сохранения и настоящий переход SQLite со старой схемы на новую.

Для следующего изменения схемы используйте вспомогательный скрипт: он оставляет снимок модели в канонической папке, учитывая связанные исходники проекта проверок.

```powershell
./scripts/add-migration.ps1 -Name NameOfChange
dotnet run --project tests/FlappyBird.Checks -c Release
```

APK находится в `src/FlappyBird/bin/<Configuration>/net9.0-android/`. Для собственного распространения настройте постоянный ключ подписи через Visual Studio; не храните ключи и пароли в Git. Trimming и AOT пока отключены для предсказуемой работы EF Core; оптимизацию размера нужно проверять отдельно на устройстве.
